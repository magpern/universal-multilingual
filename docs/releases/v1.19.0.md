**Status:** released
**Release version:** 1.19.0
**Schema target:** **10** (unchanged — no migration)
**Settings schema:** **3** (unchanged)
**Package:** `universal-multilingual-1.19.0.zip`

Patch + minor release. Fixes a routing self-loop on the language homepage and
adds an authenticated preferred-language redirect. No schema change.

## Fixed

### Language-home `redirect_canonical()` self-loop (#64)

`https://.../<code>/` for any non-default language (`/sv/`, `/de/`,
`/de-de-formal/`) 301-redirected to itself indefinitely.

`Router::resolve()` rewrites `REQUEST_URI` to the unprefixed path before core's
own canonical redirect runs, so core's `$redirect_url !== $requested_url`
guard compared the proposed target against the *stripped* URI and could not
see that it matched the URL the visitor actually requested. The front-page
canonical (`home_url('/')`), once re-prefixed by the `home_url` filter, is
exactly `/sv/` — the same URL that was requested — so the guard never fired
and the redirect looped.

`filter_redirect_canonical()` now calls `redirect_leads_to_current_request()`,
which re-applies the self-redirect guard against the original (pre-strip)
request URI, comparing scheme, host, decoded path (trailing slash
significant) and query string. Legitimate canonicalisation — `/sv` → `/sv/`,
an http → https upgrade — targets a genuinely different URL and is left to
proceed unchanged.

10 new `RoutingTest` cases.

## Added

### Authenticated preferred-language redirect

A logged-in visitor landing on an unprefixed (default-language) URL is now
redirected once to their stored Regional Preferences language
(`aiml_preferred_language` user meta), via `Router`.

- Fires only for a safe (`GET`) request from an authenticated user, and only
  when the resolved language is the site default (i.e. the request carried no
  language prefix at all).
- Never overrides a URL that already carries an explicit language prefix —
  navigating to `/en/...` on a site whose visitor prefers Swedish stays on
  `/en/...`.
- Anonymous resolution is untouched: `LanguageResolver` / anonymous routing
  stays strictly URL-authoritative (ADR-0024), which is the cache contract
  with the deployment's reverse-proxy cache. `PreferredLanguage` never
  influences anonymous resolution — only this authenticated, redirect-only
  hook.
- Reuses the existing localized-path / effective-URL resolution, so the
  redirect lands on a published translated slug when one exists, or the
  source path under the preferred language's prefix otherwise.

5 new `PreferredLanguageAuthenticatedRedirectTest` cases.

## Upgrade notes

No database migration. No settings changes. No admin-facing UI changes —
the language-home fix is transparent, and the new redirect activates
automatically for any user who already has a Regional Preferences language
set.
