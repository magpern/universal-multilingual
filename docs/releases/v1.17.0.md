## Object-level / page-level review (RVQ1, ADR-0033)

The Review Queue was a flat list of segments: post id repeated, technical field
keys dominant, approval one segment at a time, no way to say "I reviewed this
whole page" and no protection against believing a complex page is finished when
a field was missed.

It is now **object-first** — CONTENT OBJECT → LANGUAGE → FIELDS:

- **Group cards.** Pending translations are grouped by page/product and target
  language. Each card shows the object title, its type (Page / Post / Product),
  the language, a plain-language state chip (Ready to approve / Needs attention
  / Incomplete / Review complete), and a completeness summary.
- **Human field labels.** `post_title` → *Title*, `post_excerpt` → *Short
  description* (products) / *Excerpt*, `post_content` → *Description* /
  *Content*, `…:attribute_name:strength` → *Attribute: Strength*. Labels are
  produced server-side (`FieldLabelResolver`); the raw segment key stays under a
  **Technical details** disclosure on each row.
- **Approve page / Approve product.** One action approves every currently
  eligible pending segment for that object + language. It reuses the existing
  `ReviewBatchCoordinator` (same capability checks, audit, reviewer identity,
  timestamps, QA admission), is **safe-subset** — QA-blocked or conflicted
  segments are reported in `skipped`, untranslated fields are never touched —
  and processes the **entire** pending set in bounded chunks, so a page with
  more than one batch of pending fields is still fully processed.
- **Completeness-honest result.** After approval the UI shows e.g.
  *"27 approved · 2 need attention · 3 untranslated — page not fully reviewed"*
  and only reports completion when nothing is pending, missing, or rejected.
- Per-segment Approve/Reject and per-selection batch review still work inside
  each card.

### API

- `GET aiml/v1/workspace/review-queue` gains an additive `objects[]` block
  (title, type, language, per-object completeness summary, labelled field
  rows). The flat `items[]` is unchanged.
- **New:** `POST aiml/v1/workspace/<id>/review/approve-object?language=<code>` —
  permission `aiml_review_translations` + `edit_post`. Returns
  `{ approved_count, approved[], skipped[], summary }`.

### Implementation

- `src/Workspace/FieldLabelResolver.php` — server-authoritative labels.
- `src/Workspace/Review/ObjectReviewSummary.php` — completeness state composed
  from `Store::review_status_counts()` + `TranslationStatusCalculator`.
- `src/Translation/Store.php::pending_segment_keys()` — full unpaginated
  pending set for one object + language.
- `src/Workspace/WorkspaceService.php` — `review_queue_grouped()`,
  `approve_object()`.
- `src/Rest/WorkspaceController.php` — grouped response + `approve_object`
  handler + route; `get_review_queue` now defaults `page`/`per_page`.
- React: `ReviewObjectGroup`, rebuilt `ReviewQueuePanel` / `ReviewQueueRow`,
  `utils/field-labels`, `utils/object-review`, `utils/review-queue`
  (`groupQueueByObject`), `api/workspace-api` (`approveObject`).
