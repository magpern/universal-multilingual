# Universal Multilingual — Release Notes v1.15.0

**Status:** released
**Release version:** 1.15.0
**Schema target:** **10** (unchanged — no migration)
**Settings schema:** **3** (unchanged)
**Package:** `universal-multilingual-1.15.0.zip`
**Previous release tag:** `v1.14.0`
**ADR:** `docs/adr/0031-user-initiated-ai-translation.md` (Accepted)

This minor release is a **product / UX** release. The provider-agnostic AI
stack, the resumable Action-Scheduler job pipeline, Site Translate and the React
Translator Workspace already shipped; v1.15.0 makes AI translation an obvious
one-click action for a normal administrator and routes every AI translation
through the one background Jobs pipeline. There is **no database migration** —
schema stays at 10, settings shape stays at 3.

## Highlights

### Single-page "Translate with AI"

A primary **Translate with AI** action on the Translator Workspace editor
translates a page's eligible segments in one click. It:

- creates a background job and **starts it immediately** (autostart) — no
  separate "Run now" step;
- polls status (Queued → Translating → Completed), refreshes the editor, and
  reports a plain-language summary `N translated · M kept · F failed`, with any
  review need shown separately;
- offers a mode selector — **Translate missing** (default), **Retranslate
  stale**, **Retranslate AI translations**;
- is **disabled, never hidden**, when AI is not configured, with a *Configure AI
  settings* link for administrators.

### Jobs-based orchestration for everything

Page-level and bulk AI translation both create existing background jobs and
start them via an explicit `autostart` flag on `POST aiml/v1/jobs` and the Site
Translate create endpoint. Without the flag those endpoints keep their
deliberate create-then-run behaviour. `POST aiml/v1/workspace/{post_id}/translate`
is unchanged. User-facing actions carry an automatic, invisible idempotency
token: a double-click or a timeout-retry collapses to one job; a deliberate
re-run after completion is new work.

### `retranslate_machine` job type

One new job type (ADR-0031 WP0 gate). It replaces every eligible machine
translation for an object regardless of stale state. No schema change.

### Manual work is protected by design

Manual, reviewed and in-review translations are **never** overwritten by a page
or bulk AI action, in any mode. A single shared policy
(`TranslatableSegmentEligibility`) now governs the synchronous workspace
"Translate selected" path as well as the background worker and job
materialisation — closing a gap where the synchronous path could overwrite a
human's translation. Protected segments are reported as *skipped*.

### Bulk "Translate selected with AI"

Site Translate gains the same three-mode selector and a single **Translate
selected with AI** action that creates and starts the batch. Raw operational
fields (job-type enum, idempotency token, segment keys) move into an advanced
disclosure. Job status reads in plain language (Queued / Translating /
Completed / Completed with skips / Failed); execution status and review status
render as separate badges.

### Discoverability

- **Pages / Posts list table**: a *Translate with AI* bulk action opens Site
  Translate with the selected content pre-selected. No translation starts before
  a target language and mode are confirmed.
- **Legacy Translate screen**: no longer an AI dead end — it deep-links into the
  Workspace AI flow with the post and target language preselected, plus an *Open
  in Translator Workspace* link.
- **Plugins screen**: new **Settings** and **Overview** action links and a
  **Documentation** meta link.

### Shared internal navigation

A navigation bar (`.aiml-ui-subnav`, `src/Admin/AdminNavigation`) at the top of
every Universal Multilingual admin screen — Languages, Settings, Limited
Rollout, SEO Diagnostics, Translate, Workspace, Glossary, Translation Promotion.
One renderer; each tab maps to the owning screen's existing slug constant and
existing capability, so a section the current user cannot open never appears. No
JavaScript; the active tab is marked by a filled accent pill and
`aria-current="page"`.

### Shared `aiml-ui` admin design system

The `aiml-ui` tokens and components are extracted to
`assets/admin-ui/aiml-ui.css` (scoped `.aiml-ui`, no `@import`,
`wp_enqueue_style` dependency chain) and shared by Languages, Settings, the
Translator Workspace, Site Translate and Jobs. A single `<StatusBadge>` React
implementation renders execution and review state as independent axes.

### Elementor translation safety

Every AI path goes through `TranslationService` → `Store` and the existing
extractors. `_elementor_data`, widget IDs and structure are never written;
`html` / `shortcode` controls stay excluded. A dedicated round-trip regression
test asserts `_elementor_data` is byte-identical before and after a
*Retranslate AI translations* job.

### Testing / acceptance

- `tests/Fixtures/FakeAIProvider.php` (PHPUnit autoload scope) — deterministic
  provider for unit and integration tests.
- `acceptance/ai-translation-browser/` — a Playwright acceptance suite driven by
  a **self-contained** DEV-only MU-plugin that registers its own inline
  `AIProviderInterface` via the `aiml_ai_provider` filter seam. No production
  setting, no production-settable constant; removed on teardown. No paid
  provider is ever called in acceptance.

## Upgrade / compatibility

- **No migration.** `Migrator::TARGET` stays at 10; `Settings::SCHEMA_VERSION`
  stays at 3. Upgrading from 1.14.0 is a file swap.
- No change to the provider abstraction, credential vault, translation pipeline,
  Store, segment identity/hashing, or the job persistence schema.
- The generic Jobs and Site Translate create endpoints are backward compatible —
  `autostart` is opt-in.

  by `JobsRetryFailedTerminalTest` / `JobsRetryBudgetTest`.
- Two pre-existing `tsc --noEmit` errors (`OperationsPanel`, `SiteTranslatePanel`
  postType), reproduced on the clean 1.14.0 baseline; AIT1 adds none; not a CI
  gate.
