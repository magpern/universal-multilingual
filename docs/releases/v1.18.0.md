Minor release. The translation workflow scales to **many pages × many
languages**. No schema change.

## Why

The workflow was one page, one language at a time: load, translate, repeat for
every language. With ~10 languages and hundreds of pages that does not scale and
it is easy to forget a language for a page. v1.18.0 makes the operator work with
**objects × languages**, makes a forgotten language impossible to miss, and
keeps every translation / review / job rule exactly as it was.

## What's new

### Workspace — one page, many languages

- A **Languages to work on** checklist (every configured target language checked
  by default) loads a page for many languages at once.
- A **language tab strip** — one tab per selected language with its state badge.
  Clicking a tab switches the active language **without reloading the page**;
  each language's segments are fetched on first open and cached.
- An **"N / M languages ready"** bar. `M` is *every* configured target language
  (not just the ones you selected), so a forgotten language always shows; `N` is
  the languages that are complete and clean.
- **Translate all selected languages with AI** — one action creates a single
  background batch of jobs across every selected language. The current-language
  **Translate with AI** action is unchanged.

### Review Queue — grouped by object, every language together

- One card per page/product, with a tab for **every** eligible target language —
  including a language that has nothing pending, so a forgotten / untranslated
  language is never hidden behind a single-language view.
- The queue paginates by **object** (not by segment); one page's languages are
  never split across pages.
- **Approve all ready languages** approves the whole pending set for every clean
  language (processed in full — never capped at the first batch); a language
  that needs attention is reported as skipped, never silently approved, and the
  result says plainly when the object is not fully reviewed.

### Site Translate — N pages × M languages

- A target-language checklist and a pre-run count: *"5 pages × 3 languages = 15
  translations"* (page-and-language operations, not a token or cost estimate).
- Retrying a batch only creates the page-and-language pairs still missing.

### Published-language honesty

Universal Multilingual **never** changes a language's publication status and
**never** publishes content for you. But a translation written into a language
that is already published may become visible to visitors immediately under the
site's existing rendering policy — so any bulk / multi-language / N×M run
targeting a published language now **requires an explicit acknowledgement** and
is rejected server-side without it. Preview-status languages stay editor-only
and need no acknowledgement.

### Under the hood

- New `ObjectLanguageStatus` / `ObjectLanguagesSummary` — a server-authoritative
  composition over the existing read models. PHP decides every canonical
  per-(object, language) `state`; the browser renders it verbatim and never
  re-derives it.
- New REST: `GET aiml/v1/workspace/{post_id}/languages`,
  `POST aiml/v1/workspace/objects/translate` (multi-object authorization checks
  `edit_post` on every requested object; one failing object ⇒ zero jobs).
  `POST aiml/v1/workspace/{id}/review/approve-object` and
  `POST aiml/v1/site-translate/jobs` accept `languages[]` / `language_ids[]`.

## Not in this release

Fully-automatic AI translation (translate → QA → auto-submit for review) is a
separate future milestone (MLW1b) and is rejected by
`POST aiml/v1/workspace/objects/translate` in v1.18.0.

## Upgrade

Drop-in. No migration. Deactivate/reactivate is a no-op. `Migrator::TARGET`
stays 10, `Settings::SCHEMA_VERSION` stays 3.
