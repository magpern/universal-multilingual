**Schema target:** **9** (`aiml_languages.code` → `VARCHAR(20)`, `UNIQUE KEY locale`)

**Package:** `universal-multilingual-1.13.0.zip`

This minor release rebuilds the **Add a language** admin screen around
selection instead of data entry. URL language remains the anonymous authority.
Production (`biopentra.eu`) is not authorized by this release.

## Highlights

### Add a language — selection, not data entry

- The Languages screen is rebuilt on the Universal Multicurrency admin design
  system (re-prefixed and scoped; no cross-plugin CSS load, no runtime
  dependency).
- Adding a language is a choice: pick a language in a searchable
  `ComboboxControl`, pick a regional variant only when the language has more
  than one locale, set status and sort order. A read-only summary previews the
  URL prefix, locale, native name and direction.
- The server derives the URL code, English name, native name and text
  direction from a plugin-owned locale registry — **206 WordPress locales in
  162 groups**, generated offline from GlotPress locale data (no network, no
  language packs, no `intl` dependency). Values the browser submits for those
  fields are discarded.
- A gated **Advanced: custom language** disclosure keeps the raw-field path for
  locales outside the registry, behind the new `aiml_allow_custom_language`
  filter (default on).
- URL-code grammar extended to `language-region-variant`
  (`^[a-z]{2,3}(-[a-z]{2}(-[a-z0-9]+)?)?$`, ADR-0029) so explicit
  formal/orthography variants such as `de_DE_formal` route as `/de-de-formal/`.
  Derivation is deterministic and order-independent.
- On Edit, `locale` and `code` are immutable for every row; a curated row
  re-derives name/direction from the registry and takes a native-name display
  override, a custom row also allows name/direction.

### Storage

- `aiml_languages` now has a `UNIQUE KEY locale`; two languages can never share
  a WordPress locale.
- A mistyped locale can no longer be saved and silently fail to load
  translations — the locale is chosen from a list.

## Migration (schema 8 → 9)

Widens `aiml_languages.code` to `VARCHAR(20)` and adds `UNIQUE KEY locale` in
one verified `ALTER`. If an install already has two languages sharing a locale
the upgrade **pauses** — a neutral admin notice asks for each language to be
given a distinct locale — and completes automatically once the duplicate is
resolved. Existing language rows are otherwise untouched. Verified live on DEV.

## Known limitations / separate follow-up

- **Not part of this release:** a pre-existing `redirect_canonical()`
  self-redirect loop on non-default language *home* URLs (`/de/`, `/sv/`,
  `/de-de-formal/`). The branch changed no routing code; three-segment prefix
  parsing is verified. Tracked as a separate routing defect for a future
  bugfix milestone.
- `ca_valencia` and the `art_x*` variant-only locales are not first-class
  registry entries (no region segment for the grammar); reachable via custom
  mode.
