## Fixed — no Quality-checks noise on untranslated segments

The Translator Workspace segment editor ran the deterministic QA detectors on
every segment, including ones with no translation yet. For an untranslated
segment that produced a stack of warnings — `empty_translation`,
`qd9_number_corruption` (the source's digits are "missing" from an empty
target), `qd6_html_tag_loss`, and so on — even though the Status column already
says *Missing* and there is nothing to assess.

It was most visible on a freshly loaded page (before the first translate) and on
fields the AI translation flow deliberately does not touch — notably the URL
slug (`post_name`), which is owned by the separate Localized URLs feature.

`WorkspaceService::attach_meta()` and `WorkspaceService::request_suggestions()`
now return an empty QA result when the segment's target is empty. The save path
(`save_segment`) and the review path still run the full detector suite, so a
blank or malformed translation a user actually submits is still caught. This
mirrors the existing save-path behaviour, which already suppressed
`empty_translation` when clearing a translation.

Regression test:
`WorkspaceRestTest::test_untranslated_segments_carry_no_qa_noise`.

## Upgrade / compatibility

- **No migration.** `Migrator::TARGET` stays at 10; `Settings::SCHEMA_VERSION`
  stays at 3. Upgrading from 1.15.x is a file swap.
- Display-only change to the Workspace segments API response; no change to what
  is stored or to translation behaviour.

## Still open (not in this release)

- `post_name` / URL slugs are not AI-translated by "Translate missing" by
  design (Localized URLs is a separate feature). This release removes the
  misleading warnings; it does not add slug translation to the AI flow.
- A rendered page preview in place of the segment list — separate UX work.
