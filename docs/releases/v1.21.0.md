# Universal Multilingual — Release Notes v1.21.0

**Status:** released
**Release version:** 1.21.0
**Schema target:** **10** (unchanged — no migration)
**Settings schema:** **4** (was 3 — additive; no database schema change)
**Package:** `universal-multilingual-1.21.0.zip`
**Previous release tag:** `v1.20.0`

Feature release. Anonymous, not-logged-in visitors can now have an explicit
language choice remembered across visits, and can optionally be offered a
dismissible browser/location-based suggestion — while anonymous server-side
rendering stays a pure function of `host + request_uri` for a given URL, so
full-page caching is unaffected.

## Why

Language preference support previously required a logged-in account. An
anonymous storefront visitor had no way to have a language choice remembered,
or to be offered a better-matching language automatically. See
[ADR-0035](../adr/0035-anonymous-visitor-language-persistence-and-detection.md)
and the
[implementation plan](../plans/VISITOR_LANGUAGE_SELECTION_IMPLEMENTATION_PLAN.md)
for the full architecture, and
[the closure record](../plans/VISITOR_LANGUAGE_SELECTION_CLOSURE.md) for the
milestone's test/review history.

## What's new

### Anonymous visitor language persistence

- A visitor's own explicit click on the existing `[aiml_switcher]` or
  floating language selector may now be remembered in a first-party
  `aiml_visitor_lang` cookie, written and read entirely client-side. A later
  visit to the site's unprefixed/default-language URL redirects to the
  remembered language; an explicit language already in the URL always wins.
  New setting: `visitor_cookie_persist_enabled` (default **on**).
- Anonymous server-side rendering is unaffected: no PHP path reachable from
  an anonymous page render ever reads or writes this cookie (enforced by a
  narrow, named exception in `PluginGuardTest::test_no_cookie_is_set`), and
  the cookie's presence does not disable full-page caching.

### Optional browser/location suggestion

- A small, dismissible suggestion banner ("Switch to Svenska?") may appear
  based on the visitor's browser language (`navigator.languages`) and,
  optionally, their country via Universal Geo Context (no hard dependency).
  Never a silent switch. New settings: `visitor_autodetect_enabled` (master,
  default **off**), `visitor_autodetect_browser_enabled` (default on once
  the master is on), `visitor_autodetect_geo_enabled` (default off),
  `geo_language_map` (admin-owned, no shipped defaults).

### Account synchronization

- Registration seeds an empty account language preference from a validated,
  genuinely-anonymous visitor cookie. Login lets an existing account
  preference win and reissues the cookie to match it. Logout leaves the
  cookie untouched.

### No new selector

- `[aiml_switcher]` and the floating language selector remain the only
  visitor-facing language controls; the only markup change is an additive
  `data-aiml-code` attribute so one shared script can identify the selected
  language on any language link.

## Compatibility

- No database migration (`Migrator::TARGET` unchanged at 10).
- `Settings::SCHEMA_VERSION` 3 → 4, additive; existing installs get inert
  defaults until an admin explicitly enables automatic suggestions.
- Existing translations, routing, URL structure, SEO, and account
  preferences are unchanged.

## Testing

Playwright suite (20 tests), green on Chromium desktop, tablet, and mobile
viewports; WebKit mobile coverage was not exercised due to a sandbox
