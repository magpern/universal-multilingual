# Universal Multilingual — Release Notes v1.16.0

**Status:** released
**Release version:** 1.16.0
**Schema target:** **10** (unchanged — no migration)
**Settings schema:** **3** (unchanged)
**Package:** `universal-multilingual-1.16.0.zip`

Minor release. A focused Translator Workspace follow-up on top of AIT1: make the
translate → review → publish journey coherent. **No database migration.**

## Localized URL — part of translation, not a developer workflow

The "Localized URL slug" panel exposed the MSEO.1 candidate/route lifecycle
directly (Slug candidate · Generate · Save candidate · Clear · Publish route ·
Refresh). It is now a normal user surface:

- **`ensure_slug_candidate`** (`POST aiml/v1/workspace/<id>/slug/ensure`)
  generates the localized slug from the translated title automatically — on
  Workspace load, and again when a **Translate with AI** job completes. It
  reuses `SlugCandidateService::generate()`, so:
  - a **manual** slug is never overwritten;
  - a **generated** slug is refreshed only when it no longer matches the current
    translated title;
  - nothing is written on a plain page load if the slug already follows the
    title.
- The panel shows **URL for <language>** with the effective URL, an **Edit**
  action, and a plain state:
  - *Ready when Swedish is published.* (language still in preview)
  - *Ready to publish.* + a **Publish URL** button (language published, eligible)
  - *Published.* (route active)
  - *URL conflict — …* (collision)
- The technical controls (**Regenerate**, **Clear**, **Publish route**,
  **Refresh**, and the origin / sync-state / route detail) move under a
  collapsed **Advanced URL controls** disclosure. Route publication is still an
  explicit action — nothing publishes a route automatically.
- `sync_view` for a post now also returns `localized_url`, `localized_path`,
  `translated_title`, `title_slug_stale`, `state`, `language_code`,
  `language_name`, `language_published`.

### `post_name` is no longer a translation segment

The localized URL slug was also shown in the Workspace segment editor as an
editable "translation", a second write path to the same Store row that the slug
panel manages, and it produced misleading *empty translation* warnings on a
field the AI flow never touches. `WorkspaceService::load_segments()` and
`page_status()` now exclude it. Every AI and bulk path already excluded it;
`Extractor::extract()` still emits it because the slug candidate needs its
`source_text`. The legacy `Editor.php` screen is unchanged.

## Submit selected for review

The Workspace bulk toolbar gains **Submit selected for review (N)** — it submits
every selected, clean, editable, not-yet-submitted segment through the existing
`batch-review` endpoint (`action=submit`). Previously this was one click per
segment.

## "Accept TM exact" → "Apply exact memory matches"

Relabelled, with a tooltip: *"Apply the exact 100% translation-memory match to
each selected segment that has one."* It was the only bulk button with no
accessible label.

## Fixed — WooCommerce product short descriptions render translated

WooCommerce's single-product template echoes
`apply_filters( 'woocommerce_short_description', $post->post_excerpt )` — it never
calls `get_the_excerpt`, so `Renderer::filter_excerpt()` never saw it and product
short descriptions rendered in the source language even when a correct
translation was stored. `Renderer` now also filters `woocommerce_short_description`,
at **priority 1** so it substitutes the raw excerpt before WooCommerce's own
`wpautop` / `wptexturize` transform it. Product titles and long descriptions
already flowed through `the_title` / `the_content`.

## Preview honesty

When the target language is not `published`, the Workspace editor shows: *"Preview
opens the translated page for signed-in editors only — this language is not
public yet. Publish the language to make it visible to visitors."*

## Upgrade / compatibility

- **No migration.** `Migrator::TARGET` stays at 10; `Settings::SCHEMA_VERSION`
  stays at 3. Upgrading from 1.15.x is a file swap.
- No change to routing, collision, history, publication or eligibility
  semantics — only orchestration (auto-generate) and presentation.
- The slug REST endpoints (`/slug`, `/slug/generate`, `/slug/publish-route`,
  `/slug` DELETE) are unchanged; `/slug/ensure` is added.

## Not in this release
